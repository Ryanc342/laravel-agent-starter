# Skeleton

The skeleton is every block of this app, where its files live, and the arrows between the blocks. Each block and each arrow has a card in .claude/rules/skeleton/: the card is the rule for that block or arrow. There are no other rule files.

## How to read it

- This file is read in every session.
- A card is read by itself when you read or change a file in its location: the card of the block, and the card of every arrow that starts or ends there. Read a card yourself before you add a file to a block.
- Every rule applies in full. Its tag says who guarantees it:
  - `machine`: an automatic check in composer check blocks a break; the check is named after the tag.
  - `test`: a test proves it; the test is named after the tag.
  - `part`: a ready-made part of the template does it; use the part.
  - `reviewer`: only a reviewer can see a break. Its Check line says how: what to look at, what breaks the rule, what does not, and what to cite. The writing AI follows the same line.
  - `note`: a description; nothing to check.
- A rule ID is the card code and a number (ACT-3). Cite it in a finding and in a report.
- The /style page (local only) is the one design reference: every shared component and the demo of every kind of page.

## Rules for every block

### Does

- **ALL-1** composer check runs every automatic check and test (PHPStan, TypeScript, oxlint, structure checks, tests); it runs again after a push to GitHub. `note`

### Must

- **ALL-2** A change adds no function, component, hook, scope or rule list that repeats one in the repository or in the same change; what exists (Laravel, installed packages, the template's parts and components) is used first, and where one almost fits, an option is added to it. `reviewer`
  - Check: Look at: new functions, components, hooks, scopes, rule arrays, blocks of code. Break: rebuilds something the template has (table, pagination, confirm dialog, field, date helper, per-page rule, a record page, a CSV export or import), or the same logic twice (one rule array in two places, one query in two places, a pasted block). Not: two calls to one helper; look-alike code on different fields; an option added to a part. Cite: both places, or the new code and the existing part.
- **ALL-3** A value or list may exist in both PHP and TypeScript only when the backend cannot send it to the page; the same change then adds a test that compares the two copies. `reviewer`
  - Check: Look at: values, lists and logic kept in two places, mainly PHP and TypeScript. Break: one side could read the other (a TypeScript list of statuses the backend could send; a PHP literal list repeating an enum); a needed copy with no test keeping them equal. Not: generated.d.ts; hand-written page types (HTTP>WEB-4). Cite: both copies, and whether the equality test is missing.
- **ALL-4** A comparison on a record's stored fields, a user's role or ownership, or an enum's value is written only in the model, the Policy or the enum; other files call it. Type checks, null checks and UI state are not such comparisons. `reviewer`
  - Check: Look at: if, match, ternaries, where() and filter() on a record's fields, a role, ownership or an enum value outside Models, Policies and Enums. Break: an inline condition instead of the owner's method (`$task->status === Status::Done`, `$user->id === $task->user_id`, `in_array($s, ['paid', 'refunded'])`, `task.status === 'done'`). Not: owner methods and scopes, Gate, OperationGate; instanceof and null checks; UI state; refusal() combining owner calls. Cite: the line.
- **ALL-5** A new class is one of the blocks' kinds and sits at that block's location (see the overview's location tables); any other kind (a class whose name ends in Service, Repository or DTO) and any new interface needs the plan to name it. `reviewer`
  - Check: Look at: paths and class names of new files; new interfaces. Break: a class ending in Service, Repository or DTO, or a new interface, the plan does not name; a file of a known block outside its location. Not: the plan names it; traits in app/Concerns. Cite: the path and the plan section.
- **ALL-6** When code reads a relation of each record in a query's results (a loop, map, or a Resource's from()), that query loads it with with() or withCount(); for Route::listing, through a scope in its scopes list; for Route::record, through its with list. `reviewer`
  - Check: Look at: queries (get, paginate, Route::listing scopes) and the code using their results (loops, map, through, a Resource's from()). Break: a relation read or counted per record without with(), load() or withCount(); for Route::listing, no listed scope loads it; for Route::record, its with list does not name it. Not: relations in $with; model methods that are not relations. Cite: the query line and the relation line.
- **ALL-7** Code lives only where the checks read it. `machine` (Structure: FoldersTest and CodeTest (typeScriptOnly, docsMarkdownOnly, publicNoPhp, noSymlinks, importsStayInside, requiresOnlyPhp, bladeNoPhp))
- **ALL-8** app/ holds only the folders the skeleton lists. `machine` (Structure: FoldersTest, PlacementChecks::appFolders())

### Must not

- **ALL-9** Catch an error and carry on, use a default in place of a value the code needs (a missing price is not 0), or try again after a failure. Exception: an outside call may be sent once more after a network failure, when sending it twice does no harm. `reviewer`
  - Check: Look at: try/catch, rescue, retry, Http::retry, $tries, `??`, `?:`, `|| 0`, .catch(, onError. Break: a catch that carries on; a default for a required value (`$price ?? 0`); any retry. Not: rethrowing, or turning the error into a ValidationException or a shown error; a default a rule requires (ENUM-2); a default for a nullable or optional value. Cite: the line.
- **ALL-10** Switch off any check: add an ignore comment, skip a test, leave an unfinished test, or give PHPStan an ignore list or a baseline. `machine` (Structure: ConfigTest, CheckSettings::noSilencers(); phpunit.xml fails on skipped and incomplete tests)
- **ALL-11** Change the settings of the checks: PHPStan's level and paths, the layer rules, the oxlint rules, strict TypeScript, the four test suites, the steps of composer check. `machine` (Structure: ConfigTest, CheckSettings (phpstan, oxlint, typeScript, pestSuites, composerScripts, noOtherLintConfig))

## Workflow rules

### Must

- **FLOW-1** The change touches only behaviour and screens the plan names, and only files the plan names or files a rule requires for them (tests, factory, migration, generated types); each screen shows only the fields and actions the plan lists for it. `reviewer`
  - Check: Look at: the plan's decisions and screens, each screen's fields and actions; every file, route, prop and button in the diff. Break: a file or behaviour the plan does not name; a field, column, button or link not listed for its screen. Not: generated.d.ts regenerated from a named Resource; tests, factories and migrations for a named behaviour. Cite: the file or line and the plan section.
- **FLOW-2** Follow the steps of the workflow. The workflow tool records which step the plan is at, blocks a skipped step, and stops the AI once before it ends when a step is missing. `machine` (The workflow tool: scripts/workflow.php and its hooks)
- **FLOW-3** The report ends with the number of existing-debt items. At 10, it attaches a draft cleanup plan for the user to approve. The workflow tool ensures this. `machine` (The workflow tool: php scripts/workflow.php report)

### Must not

- **FLOW-4** Change code before the user says 开始 (start). The workflow tool blocks it. `machine` (The workflow tool: the PreToolUse hook)
- **FLOW-5** Change old code unless the plan names that change or the planned behaviour cannot work without it; every other problem in old code is left as it is and listed in the report as existing debt. `reviewer`
  - Check: Look at: hunks that change old lines. Break: a refactor, rename, reformat or fix of old code the planned behaviour does not need. Not: changes the plan names; old lines the new behaviour replaces. Cite: the hunk and the plan section.
