# HTTP>WEB: Backend → pages (data)

From: CTRL (Controllers), RES (Resources), MIDW (Middleware)  
To: PAGE (Pages), LAYOUT (Layouts), COMP (Components)

This card applies to every file at either end. Every rule here applies in full; the tag says who guarantees it.

## Carries

- **HTTP>WEB-1** Decisions and values the backend has worked out: values derived from records, counts, yes/no, accepted values, today's date (checked through the page rule). `note`
- **HTTP>WEB-2** Every record goes through ResourceData::from() or the listing part; a change that adds a field adds its reader, and a change that removes the last reader removes the field. `reviewer`
  - Check: Look at: Resources and their readers in pages and components. Break: a record sent without ResourceData::from() or the listing part; a new field no page or component reads; a field left after its last reader is removed. Not: fields the plan's screens show; can flags a button reads. Cite: the Resource field and the missing reader.

## Shape

- **HTTP>WEB-3** The frontend types of Resources are generated by spatie from the Resource part (resources/js/types/generated.d.ts), never written by hand; composer check checks the generated file is up to date. `machine` (composer check:static: scripts/check-generated-types.php)
- **HTTP>WEB-4** A change to a page's props, the shared data or the paginated wrapper changes the hand-written TypeScript type in the same change, field by field (name, type, null, optional). `reviewer`
  - Check: Look at: changes to a page's props, share() or the paginated wrapper, and the hand-written types in resources/js/types and the pages. Break: a prop added, removed, renamed or made nullable or optional on one side only. Not: Resource types, which are generated. Cite: both lines.

## Also applies here

- **ROUTE-4** (from ROUTE) New IDs in URLs and in page data are UUIDs; an integer ID already sent is existing debt. `reviewer`
