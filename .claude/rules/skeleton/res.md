# RES: Resources

Location: `app/Http/Resources/ (parts: ResourceShape, ResourceData, ExportsCsv)`

This card applies to every file in its location. Every rule here applies in full; the tag says who guarantees it.

## Does

- **RES-1** Turns one record into the shape the page needs: it extends the Resource part (ResourceData), its constructor lists every field with its type, and from() builds it from one record; a group of fields inside it (such as the can flags) is a ResourceShape; the fields sent are exactly the ones the constructor lists. `part`

## May use

- **RES-2** An operation's name, only to ask OperationGate whether it can run now; the answer becomes a can flag. `machine` (PHPStan: disallowedMethodCalls Operation::run() and UserlessOperation::run() (allowIn OperationController, app/Actions, app/Http/Fortify, app/Console))

## Must not

- **RES-3** Run an operation: operations run only in the operation part and in Actions. (A guard test protects this check.) `machine` (PHPStan: disallowedMethodCalls App\Actions\Operation::run(); proved by template/tests/Lint/SkeletonChecksTest.php)

## Also applies here

- **HTTP>WEB-2** (from HTTP>WEB) Every record goes through ResourceData::from() or the listing part; a change that adds a field adds its reader, and a change that removes the last reader removes the field. `reviewer`
- **HTTP>WEB-3** (from HTTP>WEB) The frontend types of Resources are generated by spatie from the Resource part (resources/js/types/generated.d.ts), never written by hand; composer check checks the generated file is up to date. `machine` (composer check:static: scripts/check-generated-types.php)
- **FREQ-4** (from FREQ) Call an Action. `machine` (PHPStan: disallowedNamespaces App\Actions in app/Http/Requests)

- POL>RES: Policies → Resources (can flags) ([card](./pol-to-res.md))
