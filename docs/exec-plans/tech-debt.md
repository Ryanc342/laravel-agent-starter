The plan (decision 3 of batch 2 feedback, Q92) was to ship Noto Sans SC Regular and Bold as static `.ttf` in `resources/fonts/` with its OFL file, load them with `@font-face` in the view, and set `laravel-pdf.dompdf` `chroot`, `font_dir` and `font_cache` in a new `config/laravel-pdf.php` (font_dir needs an existing, writable folder, e.g. `storage/fonts` with a tracked `.gitignore`). What was found: upstream (google/fonts, notofonts/noto-cjk) has no static TrueType, only the variable `NotoSansSC[wght].ttf` (17.7 MB) and CFF `.otf` that DOMPDF cannot read; static files can be cut with `fonttools varLib.instancer wght=400/700` (about 10.6 MB each). DOMPDF subsetting is already on (dompdf 3.1.6), a PDF of one Chinese title is about 10 KB and showed the characters. Blocker: with the full fonts one render peaks at 119 to 129 MB against PHP's 128 MB default, and `composer check:reference` died with "Allowed memory size exhausted" in php-font-lib. A GB2312 subset (7,904 characters, `pyftsubset`, about 2.5 MB each) peaks at 71 to 83 MB but prints rare characters as boxes. Decide: the subset (recommended) or the full fonts with a higher `memory_limit` (needs `phpunit.xml`, a protected file). Until then `print.md` says the starter ships no CJK font. | Deferred by the user on 2026-11-14 (batch 2 feedback, M3) after the memory finding; the font files and config were removed again. |
