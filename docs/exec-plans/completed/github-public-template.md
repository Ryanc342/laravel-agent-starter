## Surprises & Discoveries

- At initial inspection the repository had 69 commits and no remote, and the target repository did not exist. GitHub CLI was authenticated as `Ryanc342`.
- Initially `composer.json` declared MIT without a root license file. The upstream Laravel React starter kit declares MIT in its README rather than providing a root LICENSE file; the publication license and bundled-material attribution were subsequently reviewed.
- The original CI already ran `composer setup`, `composer check`, and `composer check:reference` with PHP 8.3, Node 22, and MySQL 8.4. Publication required the approved PHP 8.4 correction and the approved Vitest configuration correction.
- The actual `.env` is not tracked. The inspected MCP and hook configurations use relative paths or dynamically resolved project roots. At initial inspection only one Git worktree was registered and the destination directory did not exist; the rename was later verified.
- The READMEs and public repository name can change without renaming internal Ezdev rule identifiers or modifying the application's behavior.
- The committed Symfony dependencies require PHP >=8.4.1, despite the project's broad PHP constraint and existing CI's PHP 8.3 selection. The verified local runtime is PHP 8.4.20. CI must select PHP 8.4 before publication can be verified; no dependency update is needed.
- A clean `npm install` changes only the root display name in its copy of `package-lock.json` to match the checkout directory; package versions and dependency requirements remain unchanged. The original lock file is unchanged.
- The [PHP security advisory published on 2026-10-21](https://www.php.net/archive/2026.php#2026-10-21-5) fixes CVE-2026-109618 and CVE-2026-109619 in PHP 8.4.27 (also 8.5.12, 8.3.36, and 8.2.35). GitHub CI was verified using PHP 8.4.27. The local Homebrew CLI remains PHP 8.4.20 and predates those fixes; serving web traffic with that runtime requires an update. Updating the installed runtime is outside the approved CI-only change. The project's app/config/public/routes code contains no native session serialization-handler switches associated with the additional configuration-specific 2026-10-23 notice; this does not establish that an unpatched PHP runtime is safe.
