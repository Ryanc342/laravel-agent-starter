# 长期复用的 Laravel Starter Kit

## Purpose

把本项目作为长期维护、可反复创建新项目的正式 Starter Kit 发布。用户通过官方 `laravel new` 和简短包名创建项目，进入目录即可启动；安装兼容、初始化和验证由模板维护者处理。

用户验收标准：一个推荐入口，一条不含数据库选项的创建命令，默认数据库必须是 MySQL，创建后直接启动。这些条件必须同时成立，不能从“省略数据库参数”推断用户接受改成 SQLite。用户已要求开始，按本计划逐个里程碑实施和验收。

## Agreed decisions

1. 用户明确要求模板长期复用，并尽可能简单地创建新项目，体验接近官方 `laravel new`。
2. 用户认为此前方案造成困惑，要求调整计划。主要教程不再要求用户选择分发方式或理解内部初始化细节。
3. 方案主线改为：适配正式短包名，验证真实安装，发布 Packagist 稳定版本。Packagist 发布属于交付范围，不再是可选的后续阶段。
4. 用户明确要求省掉 `--database=mysql`，同时默认必须使用 MySQL。此前把省略参数解读为接受 SQLite 是助手的误解，已撤销，不是用户决策。
5. 应用和完整测试继续使用 MySQL，保留既有行锁验证。数据库选择的兼容由模板负责，不能改用 SQLite、增加隐藏的用户操作或把数据库参数加回主命令来绕过目标。
6. 用户在审阅目标、计划和前后对比后说“开始”，批准按本计划实施、验证并发布。受保护文件修改范围按 Decision Log 逐项记录；账号登录或新增授权仍在技术准备完成后按需处理。
7. 用户在了解开发副本会误用原数据库的问题后说“修”，追加批准 `scripts/worktree-up` 的一行兼容修复，使采用默认 MySQL 的项目仍为工作树分配独立数据库。

目标使用方式（实施并验收后提供）：

```sh
laravel new my-project --using=ryanc342/laravel-agent-starter
cd my-project
composer dev
```

新项目默认连接 MySQL，并按项目名分配独立的应用数据库；测试库和参考测试库继续由应用库命名派生并隔离。MySQL 已运行且账号有适当权限属于环境前提，具体凭据遵循标准配置方式。现有本地 `.env` 和用户数据保持不变，不迁移或重建已有数据库。

不要求用户先创建 GitHub 仓库、复制代码、手动分配默认数据库、补跑 `composer setup`，或记忆一组规避安装冲突的参数。可以保留原生安装器的必要提示，但默认推荐流程必须与模板实际配置一致。

必须先解决官方安装器对自定义 starter kit 的 SQLite 回写行为，再推进正式发布。不能仅更改示例命令或创建钩子早期的默认值；验收必须检查整个创建流程结束后的实际连接。如果现有官方机制无法安全满足两个条件，报告具体证据和最小兼容方案，由用户决定，不自行换数据库、改命令或改全局安装器。

## Validation

- 最终推荐命令不含 `--database`，也不通过命令别名、全局配置或隐含的额外参数补上它。创建完成后，进入目录运行 `composer dev` 即可访问应用，不需要补跑 `composer setup`。环境前提是兼容的 PHP/PDO MySQL、Composer、Node、Git，以及已运行并提供适当权限的 MySQL。
- 整个安装过程结束后，命令行应用、开发服务器和实际 PDO 连接均使用 MySQL，并连接当前项目对应的数据库；环境文件与运行配置不得出现误导性的驱动不一致。没有 MySQL 或凭据错误时应明确说明连接问题，不自动退回 SQLite。
- 走真实 Composer `create-project` 路径。发布前验证候选包，发布后通过 Packagist 实际解析目标版本再安装；GitHub URL 下载成功不算短包名验收通过。
- 普通终端按正常推荐选择即可完成。已有 Pest、Boost、测试和检查配置必须保持正确，不出现“选择一种框架但留下另一种配置”的矛盾。保留所有既有测试断言与检查强度，不以忽略错误或跳过测试解决兼容问题。
- 创建两个不同名称的项目，确认 MySQL 应用库、测试库和参考测试库分别独立，不共用回退的模板数据库或 `laravel_test`。APP_KEY 非空且不同，MySQL 中迁移表真实存在，前端 manifest 有效，Git 初始化正确，HTTP 首页可访问。不能只看安装器的成功提示或退出码。
- 验证非默认 MySQL 凭据在创建流程结束后仍然生效，参考检查和工作树隔离继续工作，不改写现有本地 `.env` 或连接源项目业务数据库。
- 初始化有单一归属，复用框架命令和官方钩子。先确定新项目数据库再迁移，避免重复生成密钥或写入模板默认库。新增逻辑通过行为测试，不写只镜像配置文字的测试。
- 两个新项目分别通过 `CI=true composer check`；模板通过该命令和 `CI=true composer check:reference`。`phpunit.xml`、`tests/Support/TestsRowLocks.php` 和现有行锁测试保持 MySQL 行为及断言，不升级第三方依赖、不新增默认 SQLite 平台要求。
- MySQL 写入验收只在 CI 临时服务或独立容器内运行，不使用开发机现有 MySQL。已有目录必须拒绝覆盖，不使用 `--force`。清理仅限本次创建的临时项目、进程、容器或明确归属的数据库。
- CI 验证本次候选提交，记录安装器、PHP、Node、MySQL 版本；同时覆盖普通交互和 AI 调用路径。GitHub 使用已修复漏洞的 PHP 8.4 补丁版，不修改本机 PHP、现有 `.env` 或全局工具配置。
- 发布独立稳定标签，拟从 `v1.0.0` 开始；先核对标签，不覆盖或批量推送旧模板标签。确认 Packagist 索引版本指向预期源码提交，再从真实包执行安装验收。
- README 只展示一个主要创建入口；版本固定、排错和其他创建方式放在后续说明。本次不改 UI；HTTP 检查用于证明安装结果能启动。

## Surprises & Discoveries

- Installer 的 DB_CONNECTION 回写正则未限定在赋值行首，也会匹配凭据中的同名字面值；模板用标准 dotenv 插值仅保护这一外部边界，保留实际密码。该保护的回归测试同时运行原生回写后解析与重复初始化，真实安装使用含该文本的临时数据库密码验证。
- 新创建流程由应用配置声明 MySQL 默认驱动，环境文件不写显式 `DB_CONNECTION`，保留原生安装器识别的注释主机默认行。这避免其 SQLite 回写破坏实际 MySQL 配置，也保留凭据。无需修改全局安装器、命令别名或增加参数。
- `scripts/worktree-up` 原先只识别显式的 `DB_CONNECTION=mysql`；新默认值形式使它无法派生工作树数据库。用户已追加批准并应用一行兼容补丁，使未写连接选项时按项目 MySQL 默认值处理。
- 当前框架的 Env 写入帮助方法未能往返保留包含引号、美元符号和反斜线的测试密码。初始化命令使用已测试的 JSON 字符串转义来保存环境值，并保持数据库名为已验证的普通标识符，以兼容现有参考检查脚本。
- 之前缺少明确的使用体验验收标准，导致方案偏向讲解分发渠道。已将“一条推荐创建命令，进入目录即可启动”写入计划，后续以此判断是否完成。
- 目标 Packagist 包在任务开始时尚未发布，原 Composer 包名为 `ezdev/ezdev-template`；元数据现已对齐 `ryanc342/laravel-agent-starter`。正式短包名还需完成公开索引与稳定版本验收，不是改一行教程。
- 用户的两个要求是“省略参数”与“默认 MySQL”，不是数据库二选一。此前计划缺少这两个条件必须同时成立的明确约束，已补入 Purpose、Agreed decisions 和 Validation；不得据此擅自更换数据库类型。
- Installer 5.28.1 在没有数据库参数时，会将自定义 starter kit 的数据库选项设置为 SQLite，并在运行初始化钩子后再次写入项目环境文件。因此仅改模板 `.env.example` 或提前写 MySQL 不能证明最终状态正确，必须验证完整流程结束后的连接。
- Composer 包入口会执行 `post-create-project-cmd`，与 GitHub URL 入口的 `composer install` 生命周期不同。当前创建钩子会生成密钥并迁移，须核对正确时机。
- 原生交互会询问测试框架和 Boost；Pest 初始化还会处理依赖、测试文件和 `.github/workflows/tests.yml`。这些兼容问题由实现和自动验收处理，不交给使用者判断。
- 如需兼容原生 Pest 所期待的工作流路径，可将现有工作流重命名为 `tests.yml` 并同步引用，保留一个完整工作流，不新增空文件或复制检查。
- [Laravel Starter Kit 文档](https://laravel.com/docs/13.x/starter-kits#community-maintained-starter-kits)定义短包名分发与 Composer 钩子；[Installer 5.28.1 源码](https://github.com/laravel/installer/blob/v5.28.1/src/NewCommand.php)用于核对真实流程。自定义模板通过 `--using` 选择，不承诺自动加入官方 React/Vue 菜单。
