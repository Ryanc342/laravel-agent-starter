### .claude/hooks/check.sh

```bash
#!/usr/bin/env bash
# 收工前检查（Claude Code 的 Stop 钩子）。
# 自上次通过以来改过代码，就跑一次 composer check；没通过就把错误交回给 AI 修。
# 只交回一次：修完还不过，AI 停下，你会看到一行提示。
input=$(cat)
cd "$CLAUDE_PROJECT_DIR" || exit 1
marker="$(git rev-parse --git-dir)/claude-check-passed"

if [ -f "$marker" ] && [ -z "$(find app bootstrap config database resources routes tests composer.json package.json -type f -newer "$marker" -print -quit)" ]; then
  exit 0
fi

if out=$(composer check 2>&1); then
  touch "$marker"
  exit 0
fi

if printf '%s' "$input" | grep -Eq '"stop_hook_active" *: *true'; then
  echo '{"systemMessage":"composer check 仍没通过，AI 已停下。回复「继续修」即可。"}'
  exit 0
fi

printf 'composer check 没通过，修好再结束。最后的输出：\n%s\n' "$(printf '%s' "$out" | tail -n 60)" >&2
exit 2
```

### .claude/hooks/plan-gate.php

```php
<?php

/*
 * 计划闸门（Claude Code 钩子，在 .claude/settings.json 里登记）。
 *   user-prompt：你发的消息是「开始」，就批准 docs/plans/ 里最新的计划
 *   pre-tool：AI 写文件之前，没有已批准的计划就拦下（docs/plans/ 除外）
 * 批准认的是计划当时的内容：计划之后被改过（追加需求、写上结果）
 * 或者有了更新的计划，批准就自动作废。
 */

$event = $argv[1] ?? '';
$input = json_decode((string) stream_get_contents(STDIN), true);
$input = is_array($input) ? $input : [];
$root = rtrim((string) (getenv('CLAUDE_PROJECT_DIR') ?: getcwd()), '/');

$plans = glob($root.'/docs/plans/*.md') ?: [];
sort($plans);
$latest = end($plans) ?: null;
$current = $latest === null ? null : basename($latest).' '.md5_file($latest);

$gitPath = trim((string) shell_exec('cd '.escapeshellarg($root).' && git rev-parse --git-path claude-approved-plan'));
$marker = $gitPath === '' ? null : (str_starts_with($gitPath, '/') ? $gitPath : $root.'/'.$gitPath);
$approved = $marker !== null && is_file($marker) ? trim((string) file_get_contents($marker)) : null;

if ($event === 'user-prompt') {
    if (preg_match('/^\s*(?:好的?|ok|okay)?\s*(?:开始|start)\s*吧?[\s\p{P}]*$/iu', (string) ($input['prompt'] ?? '')) !== 1) {
        exit(0);
    }
    if ($current === null || $marker === null) {
        echo '用户说了「开始」，但 docs/plans/ 里还没有计划（或项目不是 git 仓库）：先 grill，再写计划。';
        exit(0);
    }
    file_put_contents($marker, $current);
    echo '用户批准了计划 docs/plans/'.basename($latest).'，现在可以按计划改文件。';
    exit(0);
}

if ($event === 'pre-tool') {
    $path = (string) ($input['tool_input']['file_path'] ?? $input['tool_input']['notebook_path'] ?? '');
    if ($path === '' || ! str_starts_with($path, $root.'/') || str_starts_with($path, $root.'/docs/plans/')) {
        exit(0);
    }
    if ($current !== null && $approved === $current) {
        exit(0);
    }
    fwrite(STDERR, '还不能改 '.substr($path, strlen($root) + 1).'：没有已批准的计划。按 AGENTS.md 先 grill 用户，把计划写进 docs/plans/，等用户说「开始」。计划批准后又被改过，也要用户再说一次「开始」。');
    exit(2);
}
```

### 路由对照（URL、请求方式、路由名都不变）

| 现在 | 迁移后 |
| --- | --- |
| `Route::operation('settings/profile', UpdateProfile::class)` → profile.update | `Route::post('settings/profile', [ProfileController::class, 'update'])`，用 ProfileUpdateRequest，调用 Users/UpdateProfile::handle() |
| `Route::operation('settings/profile/delete', DeleteUser::class)` → profile.destroy | `Route::post(..., [ProfileController::class, 'destroy'])`，用 ProfileDeleteRequest，调用 Users/DeleteUser::handle()；登出照旧（logoutCurrentDevice、session invalidate、regenerateToken、回 home） |
| `Route::operation('settings/password', ChangePassword::class)->middleware('throttle:6,1')` → user-password.update | `Route::post(..., [SecurityController::class, 'update'])->middleware('throttle:6,1')`，用 PasswordUpdateRequest |
| `Route::operation('settings/passkeys/{passkey}/delete', DeletePasskey::class)->middleware('password.confirm')` → passkeys.destroy | `Route::post(..., [PasskeyController::class, 'destroy'])->middleware('password.confirm')`，`Gate::authorize('delete', $passkey)` |

### 改写规则

1. app/Actions/Users/* 和 app/Actions/Notifications/*：去掉 `extends Operation` / `UserlessOperation`，以及 ability()、subjectClass()、rules()、after() 这些方法，变成普通类。业务写入放在 `public function handle(...)` 里，参数写明类型。
2. rules()：搬进对应的 FormRequest；Fortify 动作里用 Validator，继续用 app/Concerns 里的规则 trait。
3. inputRefusal()：输入相关的检查（比如「邮箱已被占用」）写成 FormRequest 规则，报错的字段和文字跟原来一样。
4. refusal()：状态相关的检查（比如「没有未读通知」）放在 handle() 开头，不满足就 `throw ValidationException::withMessages([...])`，字段和文字跟原来一样。判断条件写成模型方法或 scope，不要散在控制器里。
5. ability()：变成 FormRequest::authorize() 里对同一个 Policy 方法的调用（updateProfile、updatePassword、deleteAccount、register、resetPassword）。没有 FormRequest 的地方（标记通知已读、删 passkey）在控制器里用 `Gate::authorize(...)`。
6. after() 的跳转和提示：写进控制器，`to_route(...)` 加上 `Inertia::flash('toast', ['type' => 'success', 'message' => ...])`，文字跟原来一样。
7. 多步写入用 `DB::transaction()`。
8. 页面上的 can.* 标志（NotificationResource、HandleInertiaRequests 的 notificationSummary）：把 `OperationGate::allows(...)` 换成 `$user->can(...)`，再加上原 refusal() 里的同一个状态判断（调用同一个模型方法），保证按钮显示和实际能不能操作一致。
9. NotificationController@index 给页面的 props 跟原来 ListingController 给的完全一样：`notifications` = `JsonResource::collection($page)->response($request)->getData(true)`，其中 $page 用 visibleTo、listOrder 两个 scope 分页，每页条数用 PerPage::fromQuery 读 per_page，每条用 NotificationResource::from()；如果测试检查了 `notificationsQuery`，也照原样给。
